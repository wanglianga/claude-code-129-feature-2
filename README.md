# 社区舞蹈队 · 排练报名与演出走位协作台

React 18 + TypeScript + Zustand + Vite 实现的单页应用。围绕**同一场演出记录**，让队长、队员、服装负责人、文化站、音响师、志愿者六类角色协同完成：报名 → 排练签到 → 走位编排 → 服装（含**尺码返换 / 备用服装**）→ 节目审查 → 演出当天 → 归档 的完整流程。

## 本地启动

### 方式一：Node 直接运行（开发）

```bash
npm install        # 安装依赖
npm run dev        # 开发模式，默认 http://localhost:5173
npm run build      # 类型检查 + 生产构建（输出 dist/）
npm run preview    # 预览生产构建，默认 http://localhost:4173
npm test           # 运行 store 层冒烟测试（44 项断言）
```

### 方式二：Docker / Compose 一键启动（生产镜像）

```bash
docker compose up --build -d      # 构建并后台启动
# 打开 http://localhost:8080
docker compose logs -f web        # 查看日志
docker compose down               # 停止
```

或仅用 Docker：

```bash
docker build -t community-dance-stage .
docker run --rm -p 8080:80 community-dance-stage
```

镜像采用多阶段构建：`node:20-alpine` 内执行 `tsc + vite build`，产物由 `nginx:stable-alpine` 静态托管（已配置 SPA 路由回退）。

## 服装尺码返换功能（本题新增）

队员**领取演出服后发现尺码偏小**，围绕同一条服装记录协同处理：

1. **试穿登记**：记录试穿照片（emoji 占位模拟上传）、**原尺码**、试穿情况、**领取人**（本人/家属代领）与期望尺码，生成返换单并通知服装负责人、队长。
2. **核对可换库存**：服装负责人按 S/M/L/XL/XXL 维护并**确认库存**；有货则安排换领（换领自动扣减库存、数字改动需重新确认），无货转队长处置。
3. **演出前换不到合适尺码**：队长二选一——
   - **调整站位**：记录走位调整说明（写入走位调整记录并通知队员/服装组）；
   - **启用备用服装**：备用服的**押金、清洗责任、归还时间重新记录**；原服押金**结转抵扣**（不再退原押金），备用服押金独立收取、归还无损时退还。
4. **押金状态同步**：未收 → 已收保管中 →（启用备用服）结转抵扣 /（归还）已退；总览、服装页、档案页徽章统一联动。
5. **长期紧缺尺码看板**：跨在办节目统计各尺码「未解决返换需求 − 当前可换库存」的缺口，并附累计上报偏小的人次，服装负责人据此判断哪些尺码长期紧缺。
6. **库存确认**：服装负责人确认当前各尺码可换库存，未确认时文化站连续性链条的「服装」环节不计完成。

## 其他功能与异常场景

- **报名**：队长发布广场舞/民族舞/合唱伴舞/节庆演出（可标记文艺汇演海选）；记录队员年龄、联系方式、服装尺码、可排练时间、是否参加正式演出、身体注意事项。
- **排练签到**：平板大按钮出勤/请假/缺席；上传曲目版本（自动通知音响师）；动作分段与重点练习成员标记；老年队员健康提醒条。
- **走位编排**：队形网格（前排高亮）；最近排练请假/缺席的队员站位标红闪烁；队员点击放置/撤下；**场地缩小**一键压缩列数，被裁队员进入「待安置」并生成调整记录与通知；队形变化说明。
- **文化站**：节目主题/人数/时长/音响需求/场地审批；节目审查（「要求调整」退回排练阶段）；报名→排练→走位→服装→审核→现场签到连续性链条；多支队伍排练室排期。
- **演出当天**：候场顺序（可提前/延后）、现场签到、现场临时通知、志愿者引导要点、音响需求确认。
- **演出档案**：签到汇总、服装归还/押金/备用服清洗归还、走位调整记录、现场照片、下次活动通知。
- **其他**：排练室多队共用（同时段同室冲突自动拦截）、老年队员健康提醒专页。
